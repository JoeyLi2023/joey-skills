# 概念归纳判断准则

## 核心问题：新建文章 vs 更新已有文章？

### 先做：与现有概念列表逐一比对

读取概念节点下所有文章标题后，逐一判断新文档的概念是否已有对应文章。

**比对不是字面匹配，而是语义匹配**：
- "Growth 策略" 和 "增长策略" 是同一个概念
- "人与算法" 和 "Human-AI Collaboration" 是同一个概念
- "职业发展" 和 "Career Building" 是同一个概念

---

## 判断树

```
新文档引入了某个概念
        ↓
现有概念列表里有语义匹配的文章？
   ├─ 是 → 在该文章末尾 append 补充段落（见下方格式）
   └─ 否 → 这个概念值得单独成文吗？
               ├─ 是 → 新建概念文章
               └─ 否 → 写进人物摘要的"关联概念"即可，不单独建文
```

---

## 什么概念值得单独成文？

**满足以下任意两条，就应该新建**：

1. **跨人物出现**：至少有两位不同的人谈到过这个主题（即使侧重不同）
2. **有实操框架**：不只是一个观点，而是有步骤、维度、或决策流程
3. **高频被引用**：在人物摘要的"关联概念"里反复出现
4. **知识库的结构化需求**：用户明确表示这个话题是他们关注的核心方向

**不应该新建的情况**：

- ❌ 一个人的独特经历（如"Adriel 开 Lyft 的那次经历"）→ 只属于人物摘要
- ❌ 只是一句金句或一个观点，没有展开逻辑 → 留在人物摘要的金句部分
- ❌ 和已有概念高度重叠，只是换了个说法 → 更新已有概念，不要新建

---

## append 补充段落的格式

在已有概念文章末尾追加时，使用以下格式：

```markdown
---

## {人物名} 的视角

{2-4句话说明这位新加入者对这个概念的具体贡献——是补充了新维度、还是提供了反例、还是在不同场景下验证了同一结论}

相关人物：[[{人物名}]]
```

**禁止**：
- ❌ 只追加一句话（太浅，不值得追加）
- ❌ 重复已有概念文章里已经写过的内容
- ❌ 把人物摘要的全文复制粘贴过来

---

## 新建概念文章的骨架

```markdown
# {概念名称}

> 来源：[[人物A]]、[[人物B]]

## 核心定义

{用2-3句话定义这个概念，从"为什么重要"出发，而不是从"是什么"出发}

## 主要视角 / 框架

{按人物或维度分小节，每节展开这个概念的一个面向}

## 跨文档共识

{多位人物在这个概念上达成的共识——这是概念文章最有价值的部分}

## 待补充 / 开放问题

{知识库还没有解答、但值得追问的方向}

## 相关人物

- [[人物A]] — 贡献了什么
- [[人物B]] — 贡献了什么
```

## 常见的错误判断

| 错误 | 正确做法 |
|------|---------|
| 看到新词就新建概念文章 | 先查是否已有语义相同的概念 |
| 把一篇文章的所有话题都归纳为概念 | 每篇文章最多提炼 2-3 个真正核心的概念 |
| 概念文章越来越像人物摘要的合集 | 概念文章要有超越单个人物的"跨文档洞察" |
| 为了对称性而新建（"已经有了A，要不要建B"） | 只有内容支撑时才新建，不要因为结构美观 |
