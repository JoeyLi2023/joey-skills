# Skill 质量自检清单

**使用方式**：Step 7 读取，skill 全部文件生成后逐条核对。P0 全部通过方可交付。

---

## P0 · 废稿级（任何一条不过 = skill 不可用）

### 架构正确性
- [ ] SKILL.md 明确写出了每个步骤读哪个文件（不是"按需读取"这种模糊描述）
- [ ] 每个 references/ 文件有且只有一个职责（没有"大而全"的单文件 skill）
- [ ] 文件间没有内容重复（同一条规则只在一个文件里写，其他地方引用）
- [ ] SKILL.md 里引用的所有文件路径都实际存在

### 内容完整性
- [ ] 每个 references/ 文件开头有使用合约（类型 / 读取时机 / 读后处理）
- [ ] 验收检查型文件有 P0 级别条目（没有 P0 = 没有真正的质量门）
- [ ] 踩过的坑以具体负面案例写出（不是"注意 X"，而是"做了 X 会导致 Y"）

### 可执行性
- [ ] AI 可以按 SKILL.md 的步骤顺序独立完成任务，不需要猜测"接下来做什么"
- [ ] 每个步骤的输出是下一步骤的输入，步骤间有明确的交接点

---

## P1 · 明显问题（影响 skill 质量和使用体验）

### 文件结构
- [ ] 没有把"选择锁死型"和"字典查阅型"混在同一个文件里
- [ ] "选择锁死型"文件有明确的"不允许"规定（不是只给选项，没有约束）
- [ ] "骨架套用型"文件的骨架是直接可粘贴的，而不是伪代码或描述性文字

### SKILL.md 质量
- [ ] 工作流步骤之间有明确的"完成标志"（怎么知道这步做完了）
- [ ] 有"如果用户答不上来 X，停下来"这类硬规则（而不是一路走到底）
- [ ] 文件加载顺序表存在，且与正文描述一致

### 知识提炼深度
- [ ] 包含了真实踩过的坑，而不只是理论上的注意事项
- [ ] 有"默认规则"机制——哪些决策 AI 可以直接做、不需要问用户
- [ ] 种子文件（如有）包含了所有结构约束，而不是靠说明文字来保障

---

## P2 · 最好有（提升 skill 的长期可维护性）

- [ ] SKILL.md 的 frontmatter description 描述精准，方便系统判断何时触发
- [ ] 有明确的"不适合这个 skill 的场景"说明（边界）
- [ ] references/ 文件设计为可独立更新——修改某一类规则不需要改 SKILL.md
- [ ] 如果 skill 可能被分发给他人，检查是否有个人/团队特有信息需要泛化

---

## 常见反模式速查

| 反模式 | 症状 | 正确做法 |
|--------|------|---------|
| 单文件大 prompt | 所有规则塞进 SKILL.md | 按使用时机拆分到 references/ |
| 内容驱动设计 | 先想"有什么知识"，再想怎么组织 | 先画工作流，再推导文件需求 |
| 泛化的正面指南 | "注意保持一致性" | 具体踩坑案例："做了 X 导致 Y，禁止 X" |
| 无约束的选择文件 | 给了选项但什么都可以选 | 有"不允许"和"默认推荐" |
| 步骤之间无交接 | 步骤 3 不知道用步骤 2 的什么结果 | 每步有明确的输入输出 |
| 一次性全部加载 | Step 0 读完所有文件 | 按步骤按需读取，用完即放 |
