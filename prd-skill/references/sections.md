# 章节骨架库

**使用方式**：Step 3 读取，按 types.md 选定的类型+体量找到对应集合，复制章节骨架填入 template.md。读完即放。

---

## S1 · 新功能 · 简单（≤ 20 行）

```markdown
# {功能名称}

## 背景 & 目标
{一句话说清为什么要做，解决谁的什么问题}

## 功能描述
{用箭头串联主流程}
{操作} → {系统行为} → {反馈}

{边界条件直接内联，不单独开章节}

## 验收标准
1. {可测试的条件，一行一个}
2. {明确触发条件和期望结果}
3. {覆盖主流程 + 至少一个异常路径}
```

## S6 · 废弃下线（简单 / 中等）

```markdown
# {功能名称} · 废弃下线

## 1. 背景
**下线原因**：{使用率低 / 被新功能替代 / 合规要求 / 其他}
**影响用户数**：{当前活跃用户数或使用频率}

## 2. 下线范围
**下线内容**：{具体列出哪些功能、页面、入口}
**保留内容**：{如有部分保留，明确说明}

## 3. 迁移方案
**用户迁移路径**：{用户应该去用什么替代功能}
**数据处理**：{历史数据保留 / 导出 / 删除，保留多久}

## 4. 下线计划
| 阶段 | 时间 | 动作 |
|------|------|------|
| 预告 | {日期} | 系统内通知用户 |
| 灰度下线 | {日期} | {操作描述} |
| 完全下线 | {日期} | 移除入口和代码 |

## 5. 验收标准
1. 用户无法再访问下线功能
2. 历史数据按方案处理完毕
3. 迁移通知已触达受影响用户
```
