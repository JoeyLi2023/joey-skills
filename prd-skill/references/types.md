# PRD 类型 + 体量定型

**使用方式**：Step 2 读取，同时做两个决策并锁死。用完即放。
**核心原则**：优先用能覆盖需求的最小档，不允许默认套复杂结构。

---

## 第一步：选类型

### 新功能（Feature）
从零新增一个用户可感知的功能模块。
**适用**：用户之前完全没有这个能力，需要新增入口、新页面、新流程。
**禁止用于**：对已有功能的小幅调整（用"迭代增强"）。

### MVP
最小可行版本，验证核心假设，有意裁剪掉非核心能力。
**适用**：新方向探索、新市场试水、快速验证。
**特征**：文档里必须有"MVP 范围"和"下一步扩展"两个明确部分，防止范围蔓延。

### 迭代增强（Enhancement）
对已有功能的改进、扩展或优化，不新增模块。
**适用**：现有功能加字段、调整交互逻辑、性能优化、体验改善。
**禁止用于**：涉及新数据表或新模块（用"新功能"）。

### 平台基建（Platform）
底层能力建设，服务于多个上层业务，用户不直接感知。
**适用**：权限系统、通知中心、工作流引擎、数据管道、SDK。
**特征**：必须有"接入方"和"接口定义"章节，消费方 > 直接用户。

### 废弃下线（Deprecation）
关闭或移除现有功能。
**适用**：功能使用率极低、被新功能替代、合规要求下线。
**特征**：必须有迁移路径和用户通知方案，不能只写"删掉"。

---

## 第二步：选体量

体量决定文档行数上限和允许的章节数。

### 简单（≤ 20 行正文）

**适用条件**（满足全部）：
- 单一交互流程，无多状态
- 边界清晰，无跨模块影响
- 无新数据结构，无权限变更

**允许章节**：背景目标 + 功能描述 + 验收标准
**不允许**：单独的"页面结构"章节、数值约束汇总表（直接内联）

### 中等（≤ 50 行正文）

**适用条件**（满足任一）：
- 涉及多端（Web + 移动）
- 有多个状态流转
- 有边界条件和异常处理
- 跨 2 个以内模块

**允许章节**：背景目标 + 需求概述 + 功能范围 + 页面结构 + 边界异常 + 验收标准

### 复杂（按需，无行数限制）

**适用条件**（满足任一）：
- 新增顶级模块
- 涉及新数据结构
- 多系统联动（3 个以上模块）
- 需要架构预审

**允许章节**：全部章节，见 sections.md 完整列表

---

## 选定后的决策锁定

类型和体量在 Step 2 选定后不再调整。如果写到一半发现体量不够，只能升档，不能降档。

| 已选类型 | 已选体量 | 对应 sections.md 章节集 |
|---------|---------|----------------------|
| 新功能 | 简单 | S1 集合 |
| 新功能 | 中等 | S2 集合 |
| 新功能 / MVP | 复杂 | S3 集合 |
| 迭代增强 | 简单/中等 | S4 集合 |
| 平台基建 | 中等/复杂 | S5 集合 |
| 废弃下线 | 简单/中等 | S6 集合 |
